## System boundaries

There are three related but independently deployed pieces:

1. **Peak spreadsheet and updater** — authoritative maintained peak data plus a
   dedicated Google Cloud Function that updates it daily.
2. **Standalone full leaderboard** — a static single-page site that reads the
   public Google Sheet directly.
3. **Dashboard Records Elo Leaderboard** — a separate Top 100 snapshot inside
   the main stats dashboard. It is generated by the dashboard backend and links
   to the standalone site for the full leaderboard.

Do not edit the main dashboard when a request concerns only the updater or the
standalone leaderboard.

## Updater behavior

Entry point: `main.py:update_peaks`; implementation: `updater.py`.

- Process all rows with a player ID across all four tabs.
- Compare ratings rounded to two decimals.
- Database rating higher: update rating and allowed metadata.
- Database rating equal: repair date/table/link metadata only.
- Database rating lower: preserve the sheet completely because a manually
  maintained peak may come from an unsupported higher-player-count game.
- Blank or `n/a` Arena rating compares as zero.
- Elo writes F, G, and M. Arena writes H and N.
- No rows are inserted, deleted, or reordered; no other columns are modified.
- F and H hyperlinks use the database `url` field.
- G is written as a numeric Google Sheets date serial with DATE number format
  `yyyy-mm-dd`, not as text. Equal Elo rows whose date is still text are repaired.
- One Sheets `batchUpdate` applies the planned requests. A protected target cell
  can reject the whole batch; initial setup encountered this and it was resolved.

## Discord behavior

The webhook value is stored only in Secret Manager:

```text
Secret: discord-elo-peaks-webhook
Function env var: DISCORD_WEBHOOK_URL
```

Only actual Elo increases from Masters and Experts are listed. Arena increases
and metadata-only repairs are excluded. Messages are ordered by **new Elo
descending**, not old Elo. Current format:

```text
__**New elo peaks: YYYY-MM-DD**__
- __Player name:__ old_elo → **new_elo**
```

If there are no qualifying increases, the body contains `- None`. Messages are
split below Discord's content limit with an underlined/bold `(continued)`
header. Successful state is persisted only after every webhook POST succeeds.

## Idempotency and the manual-run bug already fixed

Run state is stored at:

```text
gs://ark-nova-stats-dashboard-cache/elo-peak-updater/runs/
```

Scheduled retries reuse `X-CloudScheduler-ScheduleTime` as the idempotency key.
An on-demand `gcloud scheduler jobs run` was observed to send the next future
scheduled timestamp, which originally consumed the next midnight run's state.
The fix in `_scheduled_run_id()` accepts a scheduler timestamp only when it is
not more than five minutes in the future; otherwise it creates a unique
`manual-...` key. Do not remove this guard.

State flags:

```text
sheet_update_applied
notification_sent
```

They make retries resume-safe: a Discord failure retries notification without
reapplying a successful sheet batch.

## Test and deploy

Run from the updater directory:

```powershell
python -m unittest discover -s tests -v
```

The current suite has 17 tests. It covers comparison rules, metadata repair,
typed dates, `n/a` Arena handling, Discord formatting/order, tie ordering, and
resume-safe execution.

Deploy using the existing configuration:

```powershell
gcloud functions deploy update-elo-peaks `
  --gen2 `
  --runtime python311 `
  --region europe-west1 `
  --project ark-nova-stats-dashboard `
  --source . `
  --entry-point update_peaks `
  --trigger-http `
  --no-allow-unauthenticated `
  --max-instances 1 `
  --concurrency 1 `
  --timeout 540s `
  --service-account dashboard-backend@ark-nova-stats-dashboard.iam.gserviceaccount.com `
  --set-secrets DISCORD_WEBHOOK_URL=discord-elo-peaks-webhook:latest
```

An on-demand production-path run is a real external mutation and sends a
Discord message, including `- None` when no Elo peaks increased:

```powershell
gcloud scheduler jobs run update-elo-peaks-daily `
  --project ark-nova-stats-dashboard `
  --location europe-west1
```

## Diagnostics

Start with these read-only checks:

```powershell
gcloud scheduler jobs describe update-elo-peaks-daily `
  --location europe-west1 `
  --project ark-nova-stats-dashboard `
  --format=json

gcloud functions describe update-elo-peaks `
  --gen2 `
  --region europe-west1 `
  --project ark-nova-stats-dashboard `
  --format=json

gcloud logging read `
  'resource.type="cloud_run_revision" AND resource.labels.service_name="update-elo-peaks"' `
  --project ark-nova-stats-dashboard `
  --limit=30 `
  --order=desc

gcloud storage ls --recursive `
  gs://ark-nova-stats-dashboard-cache/elo-peak-updater/runs/
```

The function logs errors but does not emit a detailed success payload to Cloud
Logging. The persisted JSON state is the authoritative execution summary. Read
only selected fields to avoid dumping the large request list or Discord body.

A state filename can appear one calendar day earlier because it preserves the
offset from the Scheduler header. Use the JSON object's `created_at` timestamp
or convert the filename timestamp to UTC before assigning it to a run date.
Warnings that `httplib2` does not support per-request timeout have appeared on
otherwise successful executions and are not, on their own, a failure signal.

## Standalone leaderboard

The standalone site is one static `index.html` plus local assets. It fetches
public GViz CSV for Masters and, by default, Experts. Candidates and Ineligible
are intentionally not displayed.

Visible columns and desktop widths:

```text
# 10% | Country 10% | BGA Name 25% | Top Elo 15% |
Top Arena 12.5% | Date 15% | Top Finish 12.5%
```

Mobile widths remain fixed at 48/52/150/90/90/110/90 px with a 630px table
canvas and horizontal scrolling.

Important behavior:

- Headers use `Top Elo`, `Top Arena`, and `Top Finish`.
- Experts are included on initial load.
- Elo links use M; Arena links use N; player links use K.
- Identifier normalization accepts plain digits, trailing `.0`, a leading
  apostrophe, and comma formatting without converting through floating point.
- Missing N means no Arena link; never fall back to M.
- Blank/error/`n/a` values display as `n/a` for Arena rating and finish.
- First click sorts Elo, Arena, and Date descending; Finish ascending.
- Missing Arena sorts as 0; missing Finish as 9999.
- Desktop controls use a stable CSS grid. `html { overflow-y: scroll; }` reserves
  scrollbar width so filtering to a low-count country such as Bulgaria does not
  resize the search field.
- Alternate accounts marked `1` in D are excluded.

## Relationship to dashboard Records

The dashboard's Records Elo Leaderboard is not the standalone page. The
dashboard backend validates the public Masters worksheet, publishes the Top 100
to both dataset snapshot paths, and links users to:

```text
https://emufriends.github.io/leaderboard/
```

It currently consumes country B, player C, Peak Elo F, and Peak Arena H. It does
not include Experts and does not use the standalone page's sorting code.
